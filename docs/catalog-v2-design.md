# カタログ v2 設計（1パーツ＝1データファイル＋属性＋自動生成）

## 目的

- 追加コストを将来も一定に保つ（大きなファイルの全文書き換えを構造的になくす）
- 部位・用途・業種・テイストの4軸で検索できるようにする
- カタログページはデータから自動生成し、手動貼り付けを廃止する

## 構造

```
parts/
  manifest.json      … 登録パーツIDの配列（目録）
  DECO-0XX.json      … 1パーツの属性・説明・リンク
  DECO-0XX.svg       … ワイヤーフレーム（単体SVG）
catalog-v2.html      … 自動生成ビューア（manifest→各JSONを読み描画）
```

- gitが正。Notion DBは従（従来通り）。
- SVGをJSONに埋めず別ファイルにする理由: エスケープ不要、`<img loading="lazy">`で遅延読み込みでき表示が軽い。

## パーツJSONスキーマ

```json
{
  "id": "DECO-033",
  "name": "パーツ名",
  "category": "LAYOUT | DECO | PATTERN",
  "site": { "no": "025", "name": "参照サイト名", "url": "元サイトURL" },
  "attrs": {
    "part": ["部位"],
    "use": ["用途"],
    "industry": ["業種"],
    "taste": ["テイスト"]
  },
  "tags": ["#既存形式の形タグ"],
  "desc": "構造の要約（1〜2文）",
  "links": {
    "skeleton": "sites/NNN_x/skeleton.html",
    "composition": "sites/NNN_x/composition.md"
  },
  "svg": "parts/DECO-033.svg"
}
```

各属性は複数可。値は下記の統制語彙から選ぶ。

## 統制語彙（属性値の候補）

新しい値が必要な場合はこの表に追加してから使う（野放図な増殖を防ぐ）。

| 軸 | 候補 |
|---|---|
| 部位 (part) | ヘッダー / ナビ / ヒーロー / メイン / サイド / フッター / CTA / フォーム |
| 用途 (use) | トップページ / 会社概要 / 沿革 / 代表挨拶 / 実績 / お客様の声 / 料金表 / FAQ / 相談の流れ / お知らせ / ブランド訴求 / 問い合わせ |
| 業種 (industry) | 汎用 / 士業 / 製造 / 医療 / IT / 政治家 / 寺社・観光 / 旅館 / 老舗 |
| テイスト (taste) | ミニマル / コーポレート / 上質 / 和風 / 親しみ / 先進 / 余白極大 / 端正 |

## 追加手順（v2でのSTEP4以降）

1. `parts/DECO-0XX.json` と `parts/DECO-0XX.svg` を新規作成してpush
2. `parts/manifest.json` にIDを1行追記（ファイルは小さく保たれる）
3. Notion DBに行追加（従来通り）
4. catalog-v2.html は自動反映（編集不要）

## 移行計画（既存は一括変更しない）

1. **検証期（今ここ）**: パイロット2件（DECO-032, 033）で描画・検索を確認。既存ファイルは一切変更しない。
2. **並行期**: 新規パーツはv2形式で追加。DECO-026〜031をv2に変換（データは手元にあり低コスト）。catalog.html / catalog-live.html はそのまま残す。
3. **統合期**: 既存カード001〜025をClaude Codeで一度だけv2形式に変換（属性付与含む）。完了後、catalog-v2.html を正とし、旧catalog.htmlはアーカイブ扱いにする。
